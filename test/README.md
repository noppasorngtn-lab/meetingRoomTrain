# ทดสอบหน้าจองห้อง (UI-mrr-006) ด้วย Playwright

ทดสอบกับ stack `mrr` ในเครื่อง (`docker/docker-compose.yml`) ที่ `http://localhost:4173`
ผลรอบล่าสุด (ทุก project): **64 ผ่าน / 4 ข้าม / 0 ไม่ผ่าน** ใช้เวลาราว 60 วินาที · เคสจอง 26 เคส (chromium) + เคสเบราว์เซอร์/มือถือของ NFR-mrr-005 · เคสที่มี TC ID (019–027) เพิ่มจากการทบทวน T2 ตาม `docs/qa/qa-playbook.md`

## วิธีรัน

```
cd docker && docker compose up -d      # ต้องมี docker/.env ที่ตั้ง POSTGRES_PASSWORD
cd ../test && npm install && npx playwright test
npx playwright test --project=firefox   # รัน project เดียว (chromium, firefox, webkit-safari, edge, mobile-chrome, mobile-safari)
npx playwright show-report             # เปิดรายงาน HTML
```

`e2e/global-setup.ts` ล็อกอินเป็น `tester@mrr.local` ผ่านหน้าจอจริง (ขอรหัส → อ่านรหัสจาก mailpit :8025 → ยืนยัน)
แล้วเก็บ session ไว้ใน `.auth/` (ไม่เข้า git) ก่อนเริ่ม จะเคลียร์รหัสที่ค้างและล้างกล่องจดหมาย mailpit

## NFR-mrr-005: เบราว์เซอร์และมือถือ

`e2e/nfr-005-browsers.spec.ts` รันทุก project ใน `playwright.config.ts` (เคสจอง `booking.spec.ts` รันเฉพาะ chromium เพราะเขียนลงฐานข้อมูล)
ตรวจ 4 หน้า (UI-mrr-001, 004, 006, 007): แสดงหัวข้อ · ไม่เลื่อนซ้ายขวา · ฟอร์มจองรับวันเวลา/เลือกผู้เข้าร่วม/แจ้ง validation · คำขอส่ง `+07:00` · บนจอสัมผัสปุ่มยืนยัน/ยกเลิกกดได้ (≥ 24 px)
**ไม่เขียนฐานข้อมูล** (คำขอจองถูกตอบในเบราว์เซอร์) · เกณฑ์เป็น [Recommended] เพราะ NFR ไม่ระบุตัวเลข · รายละเอียดและข้อจำกัดใน `docs/qa/t2-coverage-report.md` หัวข้อ 5
ต้องติดตั้งเบราว์เซอร์: `npx playwright install firefox webkit` · Edge ใช้ Microsoft Edge ที่ติดตั้งในเครื่อง

## สิ่งที่ยังไม่ได้ครอบคลุม / ข้อควรรู้

- **ยังไม่มี TC-022** (จองช่วงเวลาที่ผู้จองยกเลิกแล้ว · EX-mrr-004) และ **TC-028** (จองห้องปิดปรับปรุงจริง · EX-mrr-081) เพราะต้องเตรียมข้อมูล/ขั้นตอนยกเลิกใน dev DB
- ข้อ 21 ใช้ผู้จองคนเดียวกัน เพราะ dev มีผู้ใช้ที่ล็อกอินไว้คนเดียว ไม่ได้พิสูจน์กรณี "ผู้ใช้อีกคน" ตาม EX-mrr-003

- **ข้อมูลใน dev มี 0 สิ่งอำนวยความสะดวก** จึงทดสอบการเลือกอุปกรณ์กับ API จริงไม่ได้ (เคส 18 จำลองรายการอุปกรณ์)
- **ห้องปิดปรับปรุงและผู้เข้าร่วมเกินความจุ** ไม่มีในข้อมูล dev จึงจำลอง (เคส 13–15) ไม่ได้พิสูจน์ว่า API จริงตอบแบบนั้น
  (ฝั่ง API มีเทสของมันเองใน `apps/api/test/booking/`)
- **ส่ง Email ไม่สำเร็จ** จำลองด้วย 500 ไม่ได้ทำให้ mailpit ล่มจริง
- เคส 8 และ 10 ตรวจแถวในหน้าการจองของฉันหน้าแรกเท่านั้น ถ้าการจองสะสมจนเกินหน้าแรก (เรียงตามเวลาเริ่มล่าสุดก่อน และเทสใช้วันสุ่ม 30–730 วันข้างหน้า) แถวใหม่อาจไปอยู่หน้าอื่นและเคสนี้จะล้มเหลวได้
- เคสจอง (1–27) ทดสอบกับ Chromium เท่านั้น · เบราว์เซอร์อื่นและมือถือมีเฉพาะเคส smoke ของ NFR-mrr-005 ข้างบน

## ผลข้างเคียงในฐานข้อมูล dev

เทส **ไม่ลบข้อมูลที่ตัวเองสร้าง** ตอนนี้มีการจองหัวข้อ `E2E…` ค้างอยู่ **20 รายการ** จากการรันหลายรอบ
(รอบที่เขียนเทสแล้วล้ม สร้างไว้บางส่วน) แต่ละรอบที่ผ่านสร้างเพิ่ม 6 รายการ (`CONFIRMED` 5, `PENDING_APPROVAL` 1 — เคส 8, 10, 19 พร้อมข้อมูลตั้งต้น, 21, 26)
ลบได้ด้วย: `docker exec mrr-db-1 psql -U mrr -d mrr -c "delete from bookings where title like 'E2E%'"`
(อาจต้องลบแถวใน `booking_attendees` / `booking_audit_entries` ที่อ้างถึงก่อน ถ้าติด foreign key)
