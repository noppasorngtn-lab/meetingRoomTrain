## เคสควบคุมเวลา (`e2e/t1-clock.spec.ts`)

## เคสงานตามเวลาและอีเมลล่ม (`e2e/t1-jobs.spec.ts`)

19 เคส `[real]` · **ก่อนหน้านี้งานเตือน 15 นาทีและยกเลิกอัตโนมัติไม่ได้รันจริงใน api** (มี `ReminderJob`/`AutoCancelJob` แต่ไม่มี store ต่อ Postgres และไม่ได้ลงทะเบียนใน `AppModule`) ตอนนี้ต่อแล้ว: `PgReminderStore`, `PgAutoCancelStore` (`apps/api/src/modules/*/pg-*-store.ts`) และตัวจับเวลาทุก 1 นาทีรันใน api ตามปกติ
- เทสต์เลื่อนนาฬิกา (`support/clock.ts`) แล้วสั่งงานรอบหนึ่งด้วย `POST :3000/__test/jobs/run {"titleContains":"<token>"}` — รัน `ReminderJob` และ `AutoCancelJob` ด้วย store และตัวส่งเมลจริง **เฉพาะการจองที่หัวข้อมี token** (ปฏิเสธถ้าไม่ส่ง token) กันงานที่ "เวลายืม" ไปยกเลิกการจองอื่นทั้งฐานข้อมูล
- ระหว่างที่นาฬิกาถูกเลื่อน ตัวจับเวลาของงานหยุดนิ่ง (`common/interval-runner.ts`) งานรอบเดียวที่เกิดคือที่เทสต์สั่ง
- อีเมลล่มจริง = `docker stop mrr-mailpit-1` (`support/mail.ts`) แล้ว start กลับ · `afterEach` และ `global-setup` เรียก `ensureMailUp()` ถ้าเคสค้างกลางทาง · mailpit เก็บจดหมายในหน่วยความจำ รีสตาร์ทแล้วกล่องว่าง
- พฤติกรรมที่เคสพิสูจน์: ส่งอีเมลไม่สำเร็จ → การกระทำล้มทั้งอัน (จอง/เปลี่ยนเวลา/อนุมัติ/ขอรหัส) ไม่สร้าง/ไม่เปลี่ยนข้อมูล · งานเตือนล้ม → บันทึก FAILED ไม่ส่งซ้ำ · งานยกเลิกอัตโนมัติล้ม → ยังไม่ยกเลิก รอบถัดไปทำใหม่ (transaction boundary จริงยังรอ PO: DQ-mrr-005, 014)
- **ข้อมูลค้างใน dev เพิ่มขึ้นราว 60 แถวต่อรอบเต็ม** (การจองที่มีร่องรอยลบไม่ได้ · BR-018) `book()` เลื่อนวันแล้วลองใหม่เมื่อช่วงเวลาชน · ถ้าชนบ่อยจนช้า ให้รีเซ็ตฐานข้อมูล dev (`docker compose down -v` แล้ว up ใหม่)
- `booking.spec.ts` ลบการจองของตัวเองหลังรันแล้ว (`afterAll`) แก้เคส "ห้องที่ไม่ต้องอนุมัติ → CONFIRMED" ที่เคยล้มเป็นระยะเพราะแถวค้างดันแถวใหม่ออกจากหน้าแรก
