# ทดสอบหน้าจองห้อง (UI-mrr-006) ด้วย Playwright

ทดสอบกับ stack `mrr` ในเครื่อง (`docker/docker-compose.yml`) ที่ `http://localhost:4173`
ผลรอบล่าสุด: **18 ผ่าน / 0 ไม่ผ่าน** (รันติดกัน 2 รอบผ่านทั้งคู่) ใช้เวลาราว 11 วินาที

## วิธีรัน

```
cd docker && docker compose up -d      # ต้องมี docker/.env ที่ตั้ง POSTGRES_PASSWORD
cd ../test && npm install && npx playwright test
npx playwright show-report             # เปิดรายงาน HTML
```

`e2e/global-setup.ts` ล็อกอินเป็น `tester@mrr.local` ผ่านหน้าจอจริง (ขอรหัส → อ่านรหัสจาก mailpit :8025 → ยืนยัน)
แล้วเก็บ session ไว้ใน `.auth/` (ไม่เข้า git) ก่อนเริ่ม จะเคลียร์รหัสที่ค้างและล้างกล่องจดหมาย mailpit

## สิ่งที่ยังไม่ได้ครอบคลุม / ข้อควรรู้

- **ข้อมูลใน dev มี 0 สิ่งอำนวยความสะดวก** จึงทดสอบการเลือกอุปกรณ์กับ API จริงไม่ได้ (เคส 18 จำลองรายการอุปกรณ์)
- **ห้องปิดปรับปรุงและผู้เข้าร่วมเกินความจุ** ไม่มีในข้อมูล dev จึงจำลอง (เคส 13–15) ไม่ได้พิสูจน์ว่า API จริงตอบแบบนั้น
  (ฝั่ง API มีเทสของมันเองใน `apps/api/test/booking/`)
- **ส่ง Email ไม่สำเร็จ** จำลองด้วย 500 ไม่ได้ทำให้ mailpit ล่มจริง
- เคส 8 และ 10 ตรวจแถวในหน้าการจองของฉันหน้าแรกเท่านั้น ถ้าการจองสะสมจนเกินหน้าแรก (เรียงตามเวลาเริ่มล่าสุดก่อน และเทสใช้วันสุ่ม 30–730 วันข้างหน้า) แถวใหม่อาจไปอยู่หน้าอื่นและเคสนี้จะล้มเหลวได้
- ไม่ได้ทดสอบเบราว์เซอร์อื่นนอกจาก Chromium และไม่ได้ทดสอบมุมมองมือถือ

## ผลข้างเคียงในฐานข้อมูล dev

เทส **ไม่ลบข้อมูลที่ตัวเองสร้าง** ตอนนี้มีการจองหัวข้อ `E2E…` ค้างอยู่ **8 รายการ** จากการรันหลายรอบ
(รอบที่เขียนเทสแล้วล้ม สร้างไว้บางส่วน) แต่ละรอบที่ผ่านสร้างเพิ่ม 2 รายการ (Alpha `CONFIRMED` 1, Boardroom `PENDING_APPROVAL` 1)
ลบได้ด้วย: `docker exec mrr-db-1 psql -U mrr -d mrr -c "delete from bookings where title like 'E2E%'"`
(อาจต้องลบแถวใน `booking_attendees` / `booking_audit_entries` ที่อ้างถึงก่อน ถ้าติด foreign key)
