# REQ-mrr-003

## เป้าหมาย
เพิ่ม แก้ไข ปิดปรับปรุง หรือลบข้อมูลห้องประชุม พร้อมกำหนดความจุ รูปภาพ และสิ่งอำนวยความสะดวก

**actor:** Room Administrator · **ความสำคัญ:** medium · **มีหน้าจอ:** ใช่ · **สถานะ:** draft

## ความเป็นมา

**นอกขอบเขตรอบนี้:** รูปภาพห้องประชุม — เจ้าของยอมรับเมื่อ 2026-11-24 ให้ไว้รอบถัดไป (SRC-038) ตามที่ design ตัดช่องรูปภาพออกจากฟอร์มห้อง (ADR-007 · GAP-mrr-016) · goal ยังคงถ้อยคำเดิมของลูกค้า

## ⏭ คิวส่งต่อให้ Phase 2

*ไม่มีที่ค้างอยู่* — ปิดไปแล้ว 4 ข้อ

<details>
<summary>ที่ปิดแล้ว (4)</summary>

**[DQ-mrr-001](../questions/DQ-mrr-001.md)** · การจองเก่าเก็บค่าตั้งของห้อง ณ ตอนจองไว้ยังไง
→ **ตอบ:** เก็บ id เวอร์ชันของห้อง — ข้อมูลห้องมี version ห้ามลบ

**[DQ-mrr-002](../questions/DQ-mrr-002.md)** · แก้ข้อมูลห้องแล้ว แก้เวอร์ชันเดิมได้ไหม หรือต้องสร้างเวอร์ชันใหม่เสมอ
→ **ตอบ:** สร้างเวอร์ชันใหม่เสมอ — MeetingRoomVersion ที่บันทึกแล้วแก้ไม่ได้ MeetingRoom.currentVersion ชี้เวอร์ชันล่าสุด

**[DQ-mrr-003](../questions/DQ-mrr-003.md)** · ข้อมูลห้องต้อง soft-delete / archive ไหม — §3.2 เขียนว่า "ลบข้อมูลห้องประชุม" แต่ DQ-mrr-001 ตอบว่าห้ามลบ ต้องตกลงว่า "ลบ" หมายถึงอะไร
→ **ตอบ:** ลบ = archive — ห้องเข้าสถานะ ARCHIVED (เลิกใช้งาน) ถาวร ไม่แสดงให้ค้นหาหรือจอง ข้อมูลและการจองเดิมคงไว้ เปิดกลับไม่ได้

**[DQ-mrr-004](../questions/DQ-mrr-004.md)** · หน้าจอจัดการห้องต้องแสดงประวัติเวอร์ชันของห้องไหม
→ **ตอบ:** ไม่ต้อง — หน้าจัดการห้องแสดงแค่เลขเวอร์ชันปัจจุบัน ไม่มีหน้าประวัติเวอร์ชัน (ระบบยังเก็บทุกเวอร์ชันตาม DQ-mrr-002) (SRC-039)

</details>
