## 5. NFR-mrr-005 — สิ่งที่ทำ

NFR ไม่ระบุเกณฑ์ที่วัดได้ (ช่อง "พิสูจน์ด้วย" ว่าง) **[TBD · ให้ PO ยืนยัน]** จึงนิยามเกณฑ์ปฏิบัติ [Recommended] 3 ข้อ:
1. หน้าหลักแสดงหัวข้อ และไม่เลื่อนซ้ายขวา (`scrollWidth ≤ innerWidth`)
2. ฟอร์มจองทำงานในเอนจินนั้น: ช่องวันเวลารับค่า, เลือกผู้เข้าร่วมได้, validation แสดง, คำขอส่งเวลาเป็น `+07:00`
3. บนอุปกรณ์สัมผัส ปุ่มยืนยัน/ยกเลิกกดได้ (≥ 24×24 CSS px ตาม WCAG 2.2 · 2.5.8 AA) และอยู่ในจอ

ไฟล์: `test/e2e/nfr-005-browsers.spec.ts` + projects ใน `test/playwright.config.ts`
(chromium, firefox, webkit-safari, edge, mobile-chrome=Pixel 7, mobile-safari=iPhone 14) — **ไม่เขียนข้อมูลลงฐานข้อมูล**

ผล: ทุก project ผ่าน (6–7 เคสต่อ project, 4 เคสอุปกรณ์สัมผัสข้ามบนเดสก์ท็อปโดยออกแบบ)
พิสูจน์ว่า assertion จับความผิดได้จริง: ตั้งเกณฑ์ขนาดปุ่มเป็น 500 px แล้วเคสล้ม (ปุ่มจริงกว้าง ~122 px), และยัดองค์ประกอบกว้าง 3000 px เข้าหน้าแล้วตัวตรวจ overflow เปลี่ยนเป็น true

**ยังไม่ครอบคลุม (NFR-005):**
- WebKit/Firefox ของ Playwright เป็นเอนจินตัวแทน ไม่ใช่ Safari/Firefox ที่ผู้ใช้ติดตั้งจริง และ iPhone/Pixel เป็นการจำลอง viewport + touch ไม่ใช่อุปกรณ์จริง
- ตรวจ 4 หน้า (UI-mrr-001, 004, 006, 007) ไม่ได้ตรวจปฏิทิน (005), หน้าอนุมัติ, รายงาน, หน้าผู้ดูแล
- ขนาด/ความอ่านง่ายของตัวอักษร, การเลื่อนในตาราง/ปฏิทินบนจอเล็ก และ screenshot เทียบ visual ยังไม่ได้ทำ (screenshot เก็บไว้ใน `test-results/` ให้คนดูเอง)
- การทดสอบ stack ใน dev ที่มีห้อง 0 สิ่งอำนวยความสะดวก ฟอร์มจึงไม่แสดงรายการอุปกรณ์เสริมในการตรวจ
