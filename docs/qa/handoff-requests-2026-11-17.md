## ถึง req / BA / PO

**เรื่อง: ข้อความที่อยู่ในโค้ดแล้ว แต่ไม่มีกฎหรือตัวอย่างของ req รองรับ — ขอให้ยืนยันหรือเพิ่มกฎ**

1. **ตรวจเวลาสิ้นสุดต้องหลังเวลาเริ่ม (Q1.2)** — ไม่มี BR ข้อใดพูดถึง แต่ UC-mrr-001 มี exception flow นี้ และโค้ดทำแล้ว
   - API-001 ตอบ 400 'เวลาสิ้นสุดต้องหลังเวลาเริ่ม' (`apps/api/src/modules/rooms/rooms.controller.ts`) หน้า UI-mrr-004 ตรวจก่อนส่งด้วยประโยคเดียวกัน
   - หน้าเดียวกันมีข้อความตรวจฟอร์มอีก 3 ข้อที่ dev เขียนเอง: 'วันที่ต้องเป็นวันนี้หรืออนาคต' · 'กรุณาระบุเวลาเริ่ม' / 'เวลาสิ้นสุด' · 'จำนวนผู้เข้าร่วมต้องเป็นจำนวนเต็มตั้งแต่ 1'
   - ขอ: เพิ่มกฎ (หรือบอกว่าเป็นกฎของแพลตฟอร์ม) แล้วเขียน EX พร้อมประโยคจริง
2. **ลบห้อง — ข้อความยืนยันและผลต่อการจองเดิม (Q2b)** — ไม่มี BR ของผลการลบ (มีแค่ BR-mrr-005 ว่าใครลบได้) ผลการลบอยู่ใน STM-mrr-003 ของ design เท่านั้น
   - หน้า UI-mrr-012 ถามยืนยันด้วย: 'การลบจะเลิกใช้ห้องถาวรและเปิดกลับไม่ได้ การจองเดิมคงไว้ ยืนยันลบหรือไม่' (ตัดส่วน "มีการจองในอนาคต N รายการ" ออก เพราะ API ไม่ส่งจำนวนกลับมา)
   - ขอ: ยืนยันประโยค/ตัดสินว่าต้องมีจำนวนการจองไหม และเพิ่มกฎของผลการลบ (ห้ามเปิดกลับ · การจองเดิมคงไว้)
3. **EX-mrr-106 ("ไม่แสดงห้อง B เพราะความจุไม่พอ")** — กรองตามความจุไม่มีกฎรองรับ (BR-mrr-001/012 เรื่องเวลา/ปิดปรับปรุง) โค้ดกรองแล้ว ขอกฎเรื่องความจุ
4. **ปิดค้างฝั่ง req**: DQ-mrr-003 ที่ wiki ยัง open ทั้งที่ design ตอบแล้ว (ลบ = archive) · memo รูปภาพห้อง `docs/qa/req-notice-room-photos-out-of-scope.md` รอคำตอบ Q1 (คงประโยคเดิมแล้วจดว่าเลื่อน หรือแก้ spec ผ่าน /req:change) และ Q2 (รอบหน้าเมื่อไร ต้องมี EX ไหม)
5. **(เพิ่ม 2026-11-18) `REQ-mrr-003.md` แถว EX-031/032 ยังเป็นถ้อยคำ v1 ทั้งที่ wiki เป็น v2 แล้ว** — แถว 92–93 ยังอ้าง `BR-mrr-010@v1` และหมายเหตุแถว 80 ยังบอกว่า "คงไว้ที่ @v1 · ยังไม่มีตัวอย่างพิสูจน์ v2" (commit `39e7640` เขียน wiki ใหม่ตามคำตัดสิน BA/PO ทางเลือก B แต่ REQ ไม่ถูกซิงก์)
   - ขอ: แก้แถว 92–93 และหมายเหตุแถว 80 ให้ตรง wiki · ตรวจแถว EX อื่นใน REQ-001–005 (QA ตรวจแล้ว ต่างเฉพาะ 031/032)

## ถึง design

**เรื่อง: ความไม่ตรงกันระหว่างเอกสารที่เซ็นกับโค้ด และของที่ dev เติมโดยไม่มีที่ให้ประกาศ**

1. **คำของปุ่มจองในผลค้นหา** — 3 ที่ไม่ตรงกัน: AC-mrr-106 (เซ็นแล้ว) ใช้ 'ไปหน้าจอง' · `screens.json` UI-mrr-004 action `book` ชื่อ 'จองห้องนี้' · ADR-007 ตั้งปุ่มที่ UI-mrr-005 เป็น 'ไปหน้าจองห้อง' โค้ดใช้ 'ไปหน้าจอง' ตาม AC (qa เทียบตรงตัว) ขอเลือกคำเดียว
2. **ลบห้องที่ปิดปรับปรุงอยู่** — STM-mrr-003 ให้ลบได้ แต่ช่วงปิดปรับปรุง (`room_maintenance_periods.end_at = null`) ค้างเปิดตลอด เพราะห้องที่ลบแล้วเปิดกลับไม่ได้ ขอให้ตัดสินว่าให้ปิดช่วงนั้นตอนลบไหม
3. **ขั้นยืนยันลบเป็น `window.confirm`** — UC-mrr-015 บอกว่า "ระบบยืนยัน" แต่ไม่ได้ประกาศเป็น control (ถ้าเพิ่มปุ่ม "ยืนยัน/ยกเลิก" ในหน้าจะเป็น Class B ตาม DV17) ถ้าต้องการกล่องที่ตรง theme ต้องประกาศก่อน
4. **หน้าออกจากระบบ (UI-mrr-003)** — สถานะ error บอก "แจ้งให้ลองใหม่" แต่ไม่ประกาศปุ่มลองใหม่ ผู้ใช้ต้องโหลดหน้าซ้ำ และหน้าออกจากระบบทันทีที่เปิด (ตรงกับสถานะ loading ที่ประกาศ) ขอยืนยันว่าตั้งใจ · AC-mrr-112 ข้อความ 'ออกจากระบบไม่สำเร็จ กรุณาลองอีกครั้ง' เป็นของ design เอง ไม่มี EX ของ req
5. **เส้นเก่าใน `trace.design.json`** — ADR-009 แยก FUN-mrr-015 ออกจาก FUN-mrr-014 แต่เส้น FUN-mrr-014 → UC-mrr-021 · UI-mrr-003 · API-034 ลบด้วยเครื่องมือไม่ได้ จึงค้างคู่เส้นใหม่ ด่านไม่ฟ้อง
6. **การ์ด GAP ปิดไม่ได้** (ข้อบกพร่อง plugin): GAP-mrr-001/002/004 ต้นน้ำตอบแล้วแต่ `features.json` ปิดไม่ได้เพราะโต๊ะ design ไม่มีคำตอบ

## ถึง mock

**เรื่อง: ปุ่มประจำแถวที่ wireframe วาดครั้งเดียว แต่หน้าจริงต้องวางต่อแถว**

1. **UI-mrr-004 (MCK-mrr-003)**: `view-calendar` และ `book` อยู่เหนือตารางครั้งเดียวทั้ง wireframe และ L2 (kind `navigate` ไม่อยู่ในกลุ่มปุ่มประจำแถว) แต่ปุ่ม "จอง/ดูปฏิทิน" ที่ไม่ผูกกับห้องไม่มีความหมาย โค้ดวางต่อแถว ด่านของ dev ปฏิเสธ `row_key` ของสองปุ่มนี้ ("วาดครั้งเดียว") จึงบันทึกโดยไม่มี `row_key`
2. **UI-mrr-012 (MCK-mrr-011)**: ปุ่ม `archive` (kind `delete`) อยู่ในโซน `rooms` ของ wireframe แต่ `--testids` ไม่ทำเครื่องหมาย "ต่อแถว" ให้ (dev ไม่ได้ลองส่ง `row_key` ของปุ่มนี้ จึงยืนยันไม่ได้ว่าด่านปฏิเสธ) หน้าจริงวางต่อแถวและมี `data-row-key` ที่ `<tr>` ไม่ได้
3. ขอ: ตัดสินว่า 3 ปุ่มนี้เป็นปุ่มประจำแถว แล้วให้ wireframe/mockup วาดตามนั้น (ผ่าน `screenOptions.zoneKind` หรือแจ้ง design ให้ปรับ kind) เพื่อให้ `row_key` บันทึกได้
